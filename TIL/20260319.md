## MSA

- 모놀리식 아키텍처 (MA)
  - 쪼갤 수 없는 아키텍처
  - 모든 요소를 하나의 애플리케이션에 구축
  - 간단한 배포
  - 빠른 개발
  - 부분 장애가 전체 장애로 확산
  - 구조 파악 어려움
  - 확장(스케일 아웃) 어려움
- 서비스 지향 아키텍처 (SOA)
  - 중앙 집중적 서비스, 서비스 지향적
  - SOAP: XML 기반 메시지 전달 프로토콜
  - 재사용성, 유연성, 효율성
  - 스케일 아웃 유리
- 마이크로서비스 아키텍처 (MSA)
  - 더 작고 특정 서비스에 집중한 서비스 지향적
  - SOAP보단 REST 같은 경량 프로토콜 선호

## Kubernetes, k8s

- 가상화
  ![image.png](attachment:e24abdc9-fbb7-4003-a5b1-f03cfb4fe952:image.png)
  - 가상화: 실제 리소스를 추상화하고 여러 개의 가상 환경을 생성
  - 가상 머신: 하나의 물리적 서버에서 여러 개의 독립적인 가상 서버를 운영
    - Hypervisor: 물리적 인프라 가상화, 완전 분리
    - OS 레벨 완전 제어 가능
    - OS위에 하이퍼바이저가 올라가는 형태도 존재: VirtualBox, VMware → 계층 구조로 인해 성능이 좋지 않음
  - 컨테이너 가상화: 응용 프로그래밍 및 모든 종속성을 패키지화
    - Container Engine: 운영체제 가상화 (정확히는 호스트 OS를 커널을 공유하며 OS를 격리 → OS 설정 제한됨, 격리 수준 낮음)
    - 크기가 작고 이식성이 높음
    - 오버헤드가 적음
- 쿠버네티스의 특징
  - 느슨한 결합
  - 선언적 배포
    - 명령적(imperative) vs 선언적(declarative)
    - 원하는 상태를 선언적으로 정의하여 현재 상태와 비교
  - 자동화된 스케일링
    - 자동화된 스케일링 메커니즘 제공
    - VPA: 스케일 업, 수직적 확장, Pod 내 리소스 조절
    - HPA: Pod 수 조절
    - CA: 클러스터 내 Node 개수 조절
  - 자가 치유
    - 실패한 컨테이너를 재시작
    - 노드가 죽는 경우 컨테이너들을 교체하기 위해 다시 스케줄링하여 응답하지 않는 컨테이너 종료
    - ReplicaSets
    - Liveness Probes
    - Readiness Probes
  - 범용성과 확장성을 갖춘 컨테이너 오케스트레이션 플랫폼
    - 클라우드, 온프레미스, 로컬, 멀티 및 하이브리드 클라우드 환경 지원
  - 로드밸런싱
    ![image.png](attachment:93a88829-e7e8-4d47-963b-924e5686d083:image.png)
    - Service 로드밸런싱
      - Pod 그룹에 대한 단일 endpoint 제공
      - L4 로드밸런싱 → port, ip 확인
    - Ingress 로드밸런싱
      - HTTP/HTTPS 트래픽을 클러스터 내의 서비스로 라우팅하는 규칙을 정의
- 구성 요소
  ![image.png](attachment:71933023-07ae-40c3-8949-a6c64933595f:image.png)
  - 클러스터
    - 여러 노드들로 구성된 하나의 컴퓨팅 리소스 집합
  - 노드
    ![image.png](attachment:ccd80832-605c-4cc0-8043-c106e581ad0b:image.png)
    - 컨테이너화된 애플리케이션을 실행하는 서버
    - 마스터 노드
      - 클러스터를 제어, 클러스터 상태 감시, 노드 작업 할당 및 조절
      - 컨트롤러 매니저
      - 스케쥴러로
      - api server
      - etcd
    - 워커 노드
      - 컨테이너가 실행되는 노드
      - kubelet
      - kube-proxy
      - Container Runtime
  - 쿠버네티스 오브젝트
    - 스펙과 상태 값을 갖는 엔티티
    - Pod
    - Service
    - Volume
    - Namespace
    - Ingress
  - 파드(Pod)
    - 최소 배포 단위
    - 독립적인 공간과 IP 가짐, 포트, 파일 시스템도 공유됨
  - 서비스
    - 파드들을 통해 실행되고 있는 애플리케이션을 네트워크에 노출, 통신, 로드밸런싱을 관리하는 오브젝트
    - Cluster IP
    - NodePort
    - Load Balancer
    - External Name
  - Volume
    - 파드의 일부분으로 파드와 동일한 라이프사이클을 갖는 디스크 스토리지
    - 접근하려는 각 컨테이너에 마운트하여 사용
    - EmptyDir: 파드가 실행되는 동안만 존재하는 일시적 볼륨
    - HostPath: pod가 실행되는 호스트의 파일 시스템에 접근할 수 있게하는 볼륨, 파드 삭제 후에도 데이터는 유지
    - Persistent Volume Claim: 클러스터 내에서 지속적으로 사용가능
    - ConfigMap, Secret: 설정 정보나 기밀 데이터
  - Namespace
    - 클러스터 내의 논리적 분리 단위, 리소스 격리
    - 특징
      - 리소스 격리
      - 이름 충돌 방지
      - 권한 제어
      - 환경 분리
  - Ingress
    - L7의 로드밸런서 역할, 로드밸런싱 규칙
    - 특징
      - 도메인 기반 라우팅
      - SSL/TLS 지원
      - HTTP/HTTPS 지원
      - 다양한 ingress 컨트롤러 지원 (Nginx, Kong…)
  - Label
    - 리소스를 식별하거나 그룹화하는 기능
    - 목적: 버전 관리, 환경 분리, 서비스 식별
  - 셀렉터
    - 레이블을 기반으로 동작
    - 특정 리소스를 식별하거나 선택
    - 목적: 레이블 셀렉터, 노드 셀렉터, 필드 셀렉터
  - 컨트롤러
    - 클러스터 내의 워크로드 및 리소스를 관리하고 제어하는 역할
    - ReplicaSet
    - Deployment
    - StatefulSet
    - DaemonSet
    - Job, CronJob
