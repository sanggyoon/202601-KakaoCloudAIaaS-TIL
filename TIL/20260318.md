## MemStore

- 메모리 데이터 베이스
- Redis기반 고성능 noSQL DB
- TTL 기반 데이터 만료 설정
- 구성
  - 클러스터
    - 최상위 논리 구조
    - 여러 샤드로 구성
  - 샤드
    - 데이터 분산 저장 단위, 데이터 분산 저장
    - 수평적 확장 가능
  - 노드
    - 실제 데이터 저장 장소
    - Primary + Replica
- Redis는 싱글 스레드지만 빠름 (이벤트 루프 + 메모리)
- 확장은 샤딩 기반 scale-out
- 고가용성은 Replica + Failover
- 일관성은 Primary 기준

## Load Balancer

- Scale up / Scale down
- Target Group
- Health Check
- 트래픽 분배
  - 라운드 로빈: 순서대로 분배
  - 최소 연결(Least Connection): 여유 서버에 분배
  - Source IP: 해시 테이블
- Sticky Session(고정 세션): 특정 세션의 요청을 처음 처리한 서버로만 전송하는 것

## DNS

- 레코드
  - A: ipv4
  - AAAA: ipv6
  - CNAME: 도메인을
  - MX: 메일 서버
- TTL (Time To Live): DNS Resolver가 캐싱하는 시간
- DNS 동작 흐름 (간단 요약)
  1. 클라이언트 → Resolver (로컬 DNS, 보통 ISP/회사 DNS)
  2. Resolver → Root → TLD → Authoritative DNS
  3. 최종 IP 응답 → 캐싱

## Transit Gateway

- 중앙 집중식 네트워크 전송 허브
- 다수의 VPC, 온프레미스 네트워크를 자유롭게 연결
- 라우팅 테이블 사용
- 트래픽 관리 역할 수행
- 구현 순서
  1. vpc or on-premise, 인스턴스 생성
  2. 게이트 웨이 생성
  3. 라우팅 테이블 설정

## Storage

- Block Storage
- File Storage
  - NFS 프로토콜 사용
  - 인스턴스에 마운트해서 사용
  - 파일의 트리 구조
- Object Storage
  - 버킷 타입, 버킷 내 폴더 생성
  - 버킷 공개 설정
  - 파일 접근 URL → 공유 기능
  - 메타 데이터
  - 비정형 / 반정형 데이터 저장

## CDN

- 대규모 웹 콘텐츠를 많은 사용자에게 빠르고 안정적으로 제공하는 컨텐츠 전송 네트워크 서비스
- Purge: 캐시 서버에 저장된 데이터를 삭제후 재배포 (오리진 서버의 오래된 데이터 로드 방지)
- kakao cloud에서 사라진 서비스
